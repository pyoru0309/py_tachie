# PNG / 動画を書き出す

編集したカットは、静止画として PNG、シナリオ全体として動画 (MP4 / MOV) に書き出せます。

## PNG 出力

1. 出力したいカットをタイムラインで選択します。
2. プレビューが意図した見た目になっていることを確認します。
3. ヘッダーの `PNG出力` を押します。

PNG は `projects/<project_id>/outputs/render_<timestamp>.png` に保存されます (WebGL canvas の snapshot)。
背景なしの透過 PNG として書き出したい場合は、編集パネルでカットの背景をクリアしてから書き出してください。

## 動画書き出しダイアログ

ヘッダーの `MP4出力` を押すと書き出しダイアログが開きます。

- **プリセット**: 内蔵プリセットから選びます。表は次節に。
- **エンコーダ**: HW エンコーダ (NVENC / VideoToolbox) が利用可能な環境では alternate として選択肢に並びます。利用不可なものは disabled で表示されます。
- **FPS**: `8` / `12` / `24` のいずれか。プロジェクト fps は 24 固定で、書き出し fps はそれと独立に選べます。
- **音声を含める**: 既定 ON。OFF にすると映像のみのファイル (mux 工程を skip) で出力します。透過素材をカット単位で書き出して動画編集ソフトに取り込むときに、音声トラック無しの方が便利な場合に使います。ダイアログを経由しない (= 全体設定の「動画書き出しにフォーマットを指定」が OFF の) クイック書き出し経路では常に音声が含まれます。
- **モノラル → ステレオ**: 全体設定で既定値を変更可能。
- **書き出し前確認**: ON にすると毎回ダイアログを開きます。

`書き出し` を押すと、サーバ側のバックグラウンドスレッドでフレーム生成 → ffmpeg でのエンコード → 結合が走ります。
進捗はカット単位 + フレーム単位で UI に表示され、完了後に `projects/<project_id>/outputs/` 直下にファイルが置かれます。

## 内蔵プリセット

| プリセット | 拡張子 | 想定用途 | HW alternate |
| --- | --- | --- | --- |
| MP4 (H.264) 標準 | `.mp4` | 配信プレビュー / 共有 | NVENC, VideoToolbox |
| MP4 (H.264) 高画質 | `.mp4` | 配信前マスタ | NVENC (-cq 19), VideoToolbox |
| MP4 (H.265) 高効率 | `.mp4` | サイズ重視 | HEVC NVENC, HEVC VideoToolbox |
| ProRes 422 Proxy (mov) | `.mov` | 編集ソフト取り込み (軽量) | — |
| ProRes 422 HQ (mov) | `.mov` | 視覚ロスレスの編集中間 | — |
| ProRes 4444 (mov, アルファ対応) | `.mov` | アルファ付き透過素材 | — |
| QuickTime PNG (mov, アルファ対応・完全可逆) | `.mov` | 完全可逆 + アルファ。容量大 | — |

ProRes 4444 / QuickTime PNG は背景なし (`videoTrack` も `background` も未設定) のシーンを透過動画として書き出せます。完全可逆かつアルファ対応で編集ソフトの互換性が高いのは QuickTime PNG (PNG コーデック on QuickTime) です（ファイルサイズは大きめ）。

## ハードウェアエンコーダの選び方

立ち絵システムは起動時に `ffmpeg -encoders` を解析し、利用可能なエンコーダ集合を全体設定にキャッシュします (ffmpeg を差し替えたら設定 → 全体設定の `ffmpeg のパス` を再保存することでキャッシュが更新されます)。

- **macOS (Apple Silicon)**: `h264_videotoolbox` / `hevc_videotoolbox` が標準で使えます。CPU 負荷が低く、書き出し時間も短くなります。
- **Windows + NVIDIA RTX/GTX**: NVENC ビルドの ffmpeg を導入すると `h264_nvenc` / `hevc_nvenc` が選べます。MP4 標準プリセットで RTX 3060 Laptop の実測 32 fps、Phase 3b 適用後で 62 fps の書き出しが取れました。
- HW エンコーダはファイルサイズが SW より少し大きくなりがちです。サイズを抑えたいときは SW (libx264 / libx265) のままで、画質を底上げしたいときは alternate を切り替えてください。

## 音声・BGM の扱い

- カットの音声 (`audio`) は話者ごとのセリフに紐付き、口パク解析の入力になります。
- シーンの BGM (`bgmTracks`) はカット境界をまたいで流れ続けます。1 トラックだけ `useForLipSync` を ON にすると、その BGM が口パク用の音声として扱われます (例: 歌唱配信用の伴奏 + 歌の音声を分けたい場合)。
- 動画背景 (`videoTrack`) は `cover` / `contain` / `fit` などの fit を選べます。`muted` を OFF にすると動画の音声トラックも合成されます。

## 書き出しに失敗した場合

- `ffmpeg` がインストールされ、ターミナルから `ffmpeg -version` を実行できる状態か確認してください。
- 全体設定の `ffmpeg のパス` を絶対パスで指定すると、システム PATH に依存せず動作します。
- メモリ不足 (`Killed` / OOM) になる場合は、長尺のシーンを複数シーンに分割してください (v2 GL → ffmpeg ワンパス書き出しのため、ブラウザの WebGL コンテキストと ffmpeg プロセスが主なメモリ消費源)。
- HW エンコーダで失敗するときは、ffmpeg のビルドにそのエンコーダが含まれているかを `ffmpeg -encoders | grep nvenc` などで確認してください。

## 既存出力の管理

`設定` → `出力ファイル一覧` から、過去の書き出しファイルを一覧 / 個別削除 / 全削除できます。
プロジェクトの `outputs/` を直接掃除しても問題ありません。
